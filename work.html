Subject

Paramo, the codebase under governance

Paramo is a research and backtesting system with a built execution path to a broker. No live or paper order has filled, and its trading services have been stopped since 8 October 2026.

Finding Outcomes analysis

A tick-level audit of a strategy that had passed its statistical tests showed the backtest understated losses. Its deflated Sharpe ratio fell below the 0.95 pass bar, and the strategy was retired without a trade.

Limitation

The repository is private, so it has no link and nobody outside can rerun the audit.

Control

pruvera, evidence about which model to trust

pruvera runs local AI coding agents on a sandboxed copy of Paramo, with defects planted whose correct answer is known, and scores each change by tests. It has passed no model and grants nothing.

Finding Third-party model testing

In one planted case, none of 14 local models asked before editing a file the rules say to ask about first (0 of 14). Three tried to edit it, and the permission layer refused them.

Limitation

The copy of Paramo it ran on is private, so outsiders can read the method and the harness but cannot rerun the numbers.

Control

torra, which command runs

torra is a terminal agent for Linux system work. A local model proposes a plan and never gets a shell. torra decides which proposed command runs and which waits for my approval.

Finding Approval gates

The first graded review of torra found that its classifier rated commands such as dd if=/dev/zero of=/etc/passwd and kill -9 -1 safe, so they would have run with no approval. On 4 October 2026 the rule changed so that a program torra does not recognise, or a known one writing to a system path, waits for my approval.

Limitation

The review was my own, run by an AI agent session with a grading rubric, and torra did not catch the fault. Later reviews found more commands that slipped past the new rule, and the blind red-team run has not happened.

Control

pastore, which background job runs

pastore schedules the model-heavy background jobs on my GPU machines. A job runs only as a task and model pair that I have listed with evidence, and only after it passes a contract test against a simulated model server that returns errors, refuses connections and hangs.

Finding Implementation testing

Neither of the first two jobs pastore was built to run met that contract. One recorded each model-server error as a failed result and still exited as a success, and the other retried every HTTP error. Both were fixed and passed the contract before pastore listed them.

Limitation

The faults were found by reading both jobs while pastore was being designed, and they are why every job must pass the contract test. Both jobs were mine. The model and job pairs pastore runs carry stand-in evidence, because pruvera has not yet passed any model.
