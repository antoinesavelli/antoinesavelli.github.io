How do you govern AI you can't read line by line?

Agents write the code in my systems. At this scale no person reads all of it, and I don't review the source myself. So trust has to rest on something else, and each step below leaves less of it resting on anyone's word.

My work sits between the people who build AI and the people accountable for it.

  1. Write the judgment down
  2. Make it a boundary
  3. Test what's left
  4. Say what's open

Write the judgment down

Agents start every session knowing nothing.

A written doctrine tells them how to work, when to stop and what to ask first.

A check you did not run is not a check that passed.

Never narrow a guard's scope, add an exemption, or soften a failing check to make it pass.

Approval covers only the action it was given for.

A rule on paper only asks. My most serious rule moved into code, a push gate that checks every change to risk limits and the live trading path for my recorded confirmation. An agent could type that confirmation, so it works as a tripwire that makes those changes visible.

Make it a boundary

A model can ignore a rule. It can't use a power it was never given.

torra

A local model proposes a plan and never gets a shell. torra decides which command runs, and holds anything its classifier rates dangerous, and any program it does not recognise, for my approval. A graded review found its classifier rating destructive commands as safe, so on 4 October 2026 the rule changed and an unrecognised program now waits for me. Later reviews found more that slipped past, and the blind red-team has not run.

pruvera

14 local models were told to ask before editing a protected file, and 0 of 14 asked. The permission rule refused the ones that tried. It is one test case, and it supports keeping limits outside the model.

Test what's left

Decide what counts as correct, then check the results against the data.

The $50k decision

At SimpsonScarborough I tested an LLM pipeline against pre-coded survey data, with the contracted platform as the benchmark. It came within 5 to 10% on thematic grouping and sentiment. A decision-maker approved the switch, and the $50k annual contract ended.

pruvera

It plants defects whose correct answer is known, records each study's plan in a tamper-evident log before the first trial, and scores most fixes by tests. It has passed no model and grants nothing.

Testing the testers

pruvera's graders were audited against recorded agent runs. One passed. Another showed 4 false passes in 35, and the result is published in the eval card.

pastore

When agent work is split into pieces, a separate AI session that did not build it checks each piece and never sees the builder's report. In pastore, a checker forbidden to edit anything found that one unexpected error would have stopped the scheduler.

A backtest once priced entries off the signal bar's close, using information no trader would have had at that moment. An automated test now guards against references to future data.

Say what's open

What I rely on, and how I limit it

I work with agents the way a control owner works with engineers. I set the requirements, decide what counts as correct, and test results against the data. Agents write the code, separate AI sessions review the work that is split into pieces, and I read those reports and make the call. I don't review the source myself, so the steps above exist to make the system depend on those reviews as little as possible.

That dependence is my weakest control.

Still open

  • Reviewers usually come from the same vendor as the builder, so they can share its blind spots. Since November 2026, my rules also require another company's review on ask-first changes.
  • Agents write most of the tests as well.
  • No human outside my own setup has reviewed this work.
  • Development and validation both report to me.
  • I have overridden my own rule. In August 2026 a strategy failed its 0.95 bar and I made it the engine default anyway. It was later retired with no fill.
